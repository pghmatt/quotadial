# Decisions

Choices the PRD left open, and changes the builder proposes to the PRD. When the PRD is ambiguous,
the builder picks the option that ships the current milestone fastest and records it here. Newest
entries go at the bottom of each table.

## Decisions

| D-013 | 2026-10-22 | Names: the CLI binary is `quotadial` with `qd` as an alias, the skill lives at `skills/quotadial/SKILL.md`, the MCP server is named `quotadial`, and the provider ids are `claude` and `codex`. Nothing is named `usage`. | Set by Matt. |
| D-014 | 2026-10-22 | `Provider` is written with `#[async_trait]` and has `Send + Sync` as supertraits. The method signatures are the PRD's. | A plain `async fn` in a public trait cannot be used as `Box<dyn Provider>`, which the CLI, daemon and API need, and it trips the `async_fn_in_trait` lint under `-D warnings`. |
| D-015 | 2026-10-22 | Core types: timestamps are `chrono::DateTime<Utc>` (RFC 3339 in UTC in JSON), `used_pct` is an `f64` percentage, `window_seconds` is a `u64`, and ids and names are strings. Fields the PRD marks `?` are `Option` and are left out of JSON when absent. `quotadial_core::Error` covers unreadable credentials, failed requests and unparseable responses; expired logins, rate limits and unsupported plans are snapshot statuses, not errors. | The PRD gives field names and enum values but not types. |
| D-016 | 2026-10-22 | `extra_usage` is `{ enabled, used_pct?, used?, limit?, currency? }`. The Claude provider maps `is_enabled`, `utilization`, `used_credits`, `monthly_limit` and `currency` into it, converting amounts to major currency units. | The PRD names `extra_usage` but gives it no shape. These are the fields CodexBar decodes. |
| D-017 | 2026-10-22 | `quotadial status --json` prints `{ "snapshots": [...], "errors": [{ "provider", "message" }] }`. Text output prints `no accounts found` when nothing is signed in. The exit code is 0 unless a provider fails outright, then 1. | An object can gain fields without breaking agents, and a provider that fails before finding an account has no snapshot to carry its error. |
| D-018 | 2026-10-22 | Until M1, both providers find no accounts, report `unsupported` when asked to fetch, and have no fallback. `min_poll_interval` is 5 minutes for Claude (the PRD's Anthropic floor) and 2 minutes for Codex (the PRD's fastest adaptive interval). | The brief asks for stubs that return `unsupported`. The floors are enforced in code from the start. |
| D-019 | 2026-10-22 | Until the providers have response types (M1), fixture tests check CodexBar's field names on the parsed JSON. | The harness exists without writing provider code before the go-ahead. |
| D-020 | 2026-10-22 | Milestone due dates count the PRD's week numbers from kickoff on 2026-10-22: M1 Oct 29, M2 Nov 5, M3 Nov 19, M4 Nov 26, M5 Dec 3, M6 none. | The milestone table gives weeks, not dates. |

## Proposed PRD changes

For the manager to accept or reject by editing the PRD. Until then the code follows the PRD as
written.

| # | Date | Proposal | Evidence | Status |
| --- | --- | --- | --- | --- |
| P-001 | 2026-10-22 | Make `Window.resets_at` optional. | CodexBar decodes `resets_at` as optional (`OAuthUsageWindow`, `ClaudeOAuthUsageFetcher.swift` lines 373 to 381) and keeps a window whose reset time is null, missing or unparseable (`ClaudeUsageFetcher.swift` lines 969 to 975). Its tests include `"seven_day_opus": { "utilization": 1 }` with no reset time (`Tests/CodexBarTests/ClaudeUsageTests.swift` line 675). A `credits` window has no reset at all. As written, a provider must drop such a window or invent a time. | Proposed |
| P-002 | 2026-10-22 | Make `Account.plan` and `Account.org` optional. | Every source treats them as optional. Claude: `subscriptionType` in Claude Code's credentials blob is optional (`ClaudeOAuthCredentialModels.swift` lines 129 to 136), as is the profile's organization id (`OAuthProfileResponse`, `ClaudeOAuthUsageFetcher.swift` lines 227 to 244). Codex: `plan_type` is optional (`CodexUsageResponse`, `CodexOAuthUsageFetcher.swift` line 8). As written, a provider must invent a value when either is missing. | Proposed |
| P-003 | 2026-10-22 | Correct the Codex response shape in "Provider data sources". | CodexBar decodes `wham/usage` as `plan_type`, `account_id` and `rate_limit` (singular) with `primary_window` and `secondary_window`, each `{used_percent, reset_at (Unix seconds), limit_window_seconds}`, plus `credits{has_credits, unlimited, balance}` (`CodexOAuthUsageFetcher.swift` lines 21 to 32 and 161 to 237). The PRD's `rate_limits{primary{used_percent, window_minutes, resets_at}, ...}` matches neither that nor anything CodexBar reads from rollout files, where it reads token counts only. The `codex app-server` fallback uses `rateLimits.primary{usedPercent, windowDurationMins, resetsAt}` (`UsageFetcher.swift` lines 780 to 870). The live check (#5) settles the rollout shape. | Proposed |
| P-004 | 2026-10-22 | List per-directory Keychain items in the Claude credential row. | On macOS, Claude Code stores the login for each `CLAUDE_CONFIG_DIR` in its own Keychain item named `Claude Code-credentials-` plus the first 8 hex characters of the SHA-256 of the directory path. Verified on the maintainer's Mac, where the hash of a known directory matched its item. The PRD names only `Claude Code-credentials`, which misses every account but the default one. | Proposed |
| P-005 | 2026-10-22 | Give the model a way to mark a 0% reading as unconfirmed. | "Handling every complaint and gap" puts the unconfirmed 0% rule in the M1 model, but the normalized model has no field or status for it. One option is an `unconfirmed` flag on `Window`. | Proposed |
| P-006 | 2026-10-22 | Correct the "Leveraging CodexBar" table. | Checked against CodexBar `4654968e9` (2026-10-22). Every listed file exists, but: (1) `ClaudeConfigPaths.swift` is at `Providers/Claude/`, not in `ClaudeOAuth/`, and also honours `CLAUDE_SECURESTORAGE_CONFIG_DIR`. (2) The Claude retry happens on 400, and on 403 only when the body lacks `user:profile`; the first request sends `User-Agent: claude-cli/<version> (external, cli)` and the retry `claude-code/<version>`. (3) The Claude response also carries `iguana_necktie` (cloud credits), `cedar_ember` (reset credits) and `limits[]` (scoped weekly limits), and `extra_usage` amounts are in cents. (4) CodexBar's rate gate blocks only background fetches and lets a user-initiated refresh through, which QuotaDial's 5-minute floor must not copy. (5) CodexBar refreshes only tokens it owns. It hands Claude Code's tokens back to `claude` and Codex's to the Codex CLI, and `CodexTokenRefresher.swift` is no longer called in production. (6) The Codex `account_id` comes from `tokens.account_id`; the `chatgpt_account_id` JWT claim is only a fallback. (7) `UsageFetcher.swift` has not read `~/.codex/sessions` since November 2025; it calls `codex app-server` (`account/rateLimits/read`). (8) The status fetcher tries the incident.io proxy for every host, then falls back to `summary.json` plus `components.json`. (9) There are six fetch kinds, including `webDashboard`, and each provider sets its own order. (10) Codex fixtures exist in `Tests/CodexBarTests/Fixtures/`, one level above `Providers/`. The Claude folder holds 7 terminal captures and 2 JSON files, and OAuth usage responses appear only inline in tests. | Proposed |
| P-007 | 2026-10-22 | Plan for the macOS Keychain prompt in the "no login, first number in under 60 seconds" promise. | On macOS, the Claude login lives only in the Keychain, and reading Claude Code's item from another app shows an access prompt. CodexBar makes this read opt-in because Claude Code rewrites the item's access list on every token refresh, so "Always Allow" does not stick (`ClaudeOAuthDirectKeychainReadConsent.swift` lines 3 to 17). Without a plan, Mac users see a system prompt on first run and again after each refresh. | Proposed |
