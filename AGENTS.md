# QuotaDial agent guide

QuotaDial tracks AI coding-subscription usage limits on macOS, Windows and Linux. Version 1 covers
Claude and ChatGPT/Codex. It reads the OAuth credentials the official CLIs already store, calls each
provider's usage endpoint, normalizes the result, and serves it through a tray app, a CLI
(`quotadial`, alias `qd`), a local HTTP API, an MCP server and a SKILL.md. It is sold with a free
and a Pro tier. Domains: quotadial.com and quotadial.app.

Stack: Rust core (reqwest, tokio, rusqlite, axum, keyring), a Tauri 2 + TypeScript/React tray app,
and a thin CLI.

## Source of truth and roles

- The PRD is the source of truth for endpoints, the normalized model, architecture and milestones.
  Follow it. Do not re-research or re-decide anything it settles.
- The full PRD, `docs/PRD.md`, is private and gitignored: it holds competitor research and pricing.
  The repo carries `docs/PRD-public.md`, generated by `scripts/public-prd.sh` as
  `docs/PUBLIC_SCOPE.md` describes. Regenerate and commit it after every PRD edit. CI fails if
  `docs/PRD.md` is ever tracked or the public copy contains private content.
- Manager: Claude (claude.ai session) reviews through the GitHub repo and edits the PRD. Builder:
  the Codus brain. The builder never edits the PRD; it proposes changes in `docs/DECISIONS.md`.
- The manager leaves instructions in GitHub issues, PR reviews and comments. Check them at the
  start of every turn, and read every review on a PR before merging it.
- `docs/DECISIONS.md` records every choice the PRD left open and every proposed PRD change.
- `docs/TASK_TRACKER.md` records progress and implementation notes. Update it with every change.
- CodexBar (MIT, Peter Steinberger, https://github.com/steipete/CodexBar) is the reference
  implementation we port provider logic from. Keep a clone at `../codexbar-ref`. Port the logic,
  name the CodexBar source file in the module docs, and never vendor its UI. Credit lives in
  `NOTICE`.

## Layout

| Path | Contents |
| --- | --- |
| `crates/core` (`quotadial-core`) | Normalized model (`Account`, `Window`, `Snapshot`, `Status`) and the `Provider` trait |
| `crates/poll` (`quotadial-poll`) | When a provider may be asked for usage (the floor, 429 backoff, replay from the cache) and the per-account state files, shared by every provider |
| `crates/daemon` (`quotadial-daemon`) | The daemon: the one poller every consumer shares, SQLite history, the single-instance lock |
| `crates/providers/claude` (`quotadial-provider-claude`) | Claude provider |
| `crates/providers/codex` (`quotadial-provider-codex`) | ChatGPT/Codex provider |
| `crates/providers/all` (`quotadial-providers`) | The list of providers QuotaDial ships, used by the CLI and the tray app |
| `crates/api` (`quotadial-api`) | The local HTTP API (the daemon's server on 127.0.0.1, its bearer token, and the client the CLI uses to ask the daemon), the `quotadial` MCP server, and `Host`, which runs the daemon for `quotadial daemon` and the tray app |
| `crates/cli` (package `quotadial`) | The `quotadial` and `qd` binaries |
| `apps/tray` | The Tauri 2 tray app: a Preact and TypeScript window (`src/`) and the Rust app in `src-tauri/`, its own Cargo workspace, which runs the daemon and draws the meter |
| `skills/quotadial/SKILL.md` | The agent skill: when and how agents check usage, and the HTTP API's shape |
| `fixtures/<provider>/` | Redacted or synthetic provider responses used by tests |
| `scripts/` | Repo tooling, such as `public-prd.sh` |
| `docs/` | Public PRD, public-scope rule, decisions log, task tracker |

## Conventions

- Conventional Commits: `feat:`, `fix:`, `docs:`, `test:`, `refactor:`, `ci:`, `chore:`, with a
  scope where it helps (`feat(claude): parse weekly window`). Keep commits small, one concern each.
- One crate per provider under `crates/providers/<name>`, each implementing
  `quotadial_core::Provider`. Provider-specific code stays out of core, the CLI, the API and the
  tray app.
- Every `Window` in a `Snapshot` carries `fetched_at` and `source`. Nothing reaches a user without
  its age and origin.
- Never write provider credential files or keychain entries. QuotaDial only reads what the official
  CLIs store. Refreshing or re-authenticating is the CLI's job.
- Never print, log or commit tokens, cookies or API keys. That includes error messages, `Debug`
  output, test snapshots and fixtures. Redact before a value leaves the function that read it.
  Text from outside, such as a server's error message or a model's name, goes through
  `quotadial_core::outside_text` before it reaches a `Snapshot`, and the CLI applies
  `redact_secrets` again.
- Unredacted captures live under `fixtures/**/raw/`, which is gitignored. Only redacted or
  synthetic fixtures are committed. See `fixtures/README.md`.
- Poll Anthropic usage endpoints no more than once every 5 minutes per account. Enforce the floor in
  code.
- QuotaDial's own cache lives in the OS cache directory under `quotadial/`, with private file
  permissions. It holds derived data only (snapshots, times, counters), never a token.
- The local API listens on `127.0.0.1` only. Its bearer token is QuotaDial's own and lives only in
  `token` in the data directory (0600): print where it is, never its value, and send it only while
  `daemon.lock` shows a daemon running.
- Tests never touch the real Keychain, the official CLIs' files or the network. Inject fakes and a
  local HTTP server instead. The one exception is an `#[ignore]`d test that runs only with
  `QUOTADIAL_REAL_KEYCHAIN_TESTS=1`, which CI never sets.
- `cargo fmt`, `cargo clippy -D warnings` and `cargo test` must pass on macOS, Windows and Linux
  before anything merges to `main`. CI enforces this and `main` is protected.

## Commands

```sh
cargo build --workspace                                 # build everything
cargo test --workspace                                  # run every test
cargo clippy --workspace --all-targets -- -D warnings   # lint, exactly as CI runs it
cargo fmt --all                                         # format (CI runs it with -- --check)
cargo run -p quotadial -- status                        # usage status as text
cargo run -p quotadial -- status --json                 # the same as JSON
cargo run -p quotadial --bin qd -- status               # via the qd alias
scripts/public-prd.sh                                   # regenerate docs/PRD-public.md
scripts/public-prd.sh --check                           # the public-copy check CI runs
```

The tray app, from `apps/tray` (its Rust side is a separate workspace in `src-tauri`):

```sh
npm ci                                   # the window's dependencies
npm run build                            # type-check, build the window, check its 150 KB budget
npm run cli                              # build the CLI the app bundles (Tauri needs it to compile)
(cd src-tauri && cargo test)             # the app's tests; also cargo fmt and clippy, as CI runs them
npx tauri dev                            # run the app from source
npx tauri build                          # the app and its installer, in src-tauri/target/release/bundle
```
